  <action>
Modify `.github/workflows/release.yml` with these changes:

**1. Add tag trigger to `on.push`:**

```yaml
on:
  push:
    branches: [main]
    paths:
      - 'composeApp/**'
      - 'api-client/**'
      - 'gradle/**'
      - 'build.gradle.kts'
      - 'settings.gradle.kts'
      - 'gradle.properties'
      - 'gradlew'
      - 'gradlew.bat'
    tags:
      - 'v*'
  workflow_dispatch:
    inputs:
      version:
        description: 'Version name (e.g. 1.2.3). Leave empty to auto-detect from tags.'
        required: false
        type: string
```

NOTE: `tags` must be a sibling of `branches` under `push`, not nested. GitHub Actions treats `push` with both `branches`+`paths` and `tags` as: tag pushes matching `v*` trigger the workflow (paths filter does NOT apply to tags), AND branch pushes matching `main` with the path filter also trigger it.

**2. Update the "Resolve release version" step** to detect tag pushes:

Replace the existing version resolution step with logic that checks `GITHUB_REF` for a tag:

```yaml
      - name: Resolve release version
        id: version
        run: |
          if [[ "$GITHUB_REF" == refs/tags/v* ]]; then
            VERSION="${GITHUB_REF#refs/tags/v}"
          else
            RAW="${{ inputs.version || steps.changelog.outputs.next_version || 'nightly' }}"
            VERSION="${RAW#v}"
          fi
          echo "tag=v${VERSION}" >> "$GITHUB_OUTPUT"
          echo "name=${VERSION}" >> "$GITHUB_OUTPUT"
```

**3. Update `build-linux-flatpak` job condition** to also run on tag pushes:

Change:
```yaml
    if: github.event_name == 'workflow_dispatch'
```
To:
```yaml
    if: github.event_name == 'workflow_dispatch' || startsWith(github.ref, 'refs/tags/v')
```

**4. Update `create-release` job condition for versioned release** to also fire on tag pushes:

Change the existing condition on "Create versioned release" step:
```yaml
        if: github.event_name == 'workflow_dispatch'
```
To:
```yaml
        if: github.event_name == 'workflow_dispatch' || startsWith(github.ref, 'refs/tags/v')
```

**5. Update nightly condition** to exclude tag pushes (it should only run on branch pushes):

Change the condition on "Update nightly pre-release" step:
```yaml
        if: github.event_name == 'push'
```
To:
```yaml
        if: github.event_name == 'push' && !startsWith(github.ref, 'refs/tags/')
```

**6. Handle `create-release` `needs` for optional Flatpak:**

The `create-release` job currently has `needs: [resolve-version, build-android, build-macos, build-linux-flatpak]`. Since `build-linux-flatpak` is conditional (skipped for nightly), this will fail for nightly builds unless we account for it.

Check current behavior: if `build-linux-flatpak` is skipped via `if`, GitHub Actions treats it as "skipped" not "failed", so `needs` should still pass. Verify this is the existing behavior for nightly (it must be working today since nightly doesn't build Flatpak). If the workflow currently works for nightly with this `needs` list, no change is needed here.

Actually, looking at the current workflow: `create-release` needs `build-linux-flatpak`, but `build-linux-flatpak` only runs on `workflow_dispatch`. For nightly pushes to main, `build-linux-flatpak` is skipped — yet the `create-release` job must still run. This means GitHub Actions is already handling skipped jobs in `needs` gracefully (the default behavior is that skipped dependencies are treated as satisfied). No change needed.
