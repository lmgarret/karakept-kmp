    **Investigation approach:** The `rememberSaveable(key = "main_screen_list_state", saver = LazyListState.Saver)` on line 137 of MainScreen.kt should preserve scroll state across Voyager push/pop. The bug has these likely root causes (investigate in order):

    **Root cause 1 (most likely): Data-driven recomposition.** When the user opens the reader (Voyager push), background sync or state changes may update the `bookmarks` list, `bookmarkListVersion`, or `currentFilter`. If the `LazyColumn` key changes or the items change while the screen is off-screen, Compose may re-layout and reset scroll position. Check:
    - Does `MainScreenScrollAction` or any `LaunchedEffect` call `listState.scrollToItem(0)` or `listState.animateScrollToItem(0)` when data changes?
    - Look for `screenModel.scrollToTop()` triggers that fire on bookmark list updates
    - Check if `bookmarkListVersion` changes trigger scroll-to-top via the `MainScreenScrollAction`

    **Root cause 2: Voyager SaveableStateRegistry.** Voyager's `object Screen` might not properly save/restore `rememberSaveable` state for singleton screens. Check if `MainScreen` is declared as `object MainScreen : Screen` or `data object MainScreen : Screen`.

    **Fix approach (apply based on what investigation reveals):**

    A. If `MainScreenScrollAction` scrolls to top on data change: Add a guard so it only scrolls to top on USER-initiated data changes (new filter, manual refresh), not background sync. The scroll-to-top should NOT trigger while the screen is not the top of the Voyager stack.

    B. If `rememberSaveable` state is lost: Hoist the scroll position into `MainScreenModel` (which is `single {}` in Koin, so it survives navigation). Store `firstVisibleItemIndex` and `firstVisibleItemScrollOffset` in the ScreenModel. On re-composition, initialize `LazyListState` from these stored values using `LazyListState(firstVisibleItemIndex, firstVisibleItemScrollOffset)`.

    C. If both: Apply both fixes.
