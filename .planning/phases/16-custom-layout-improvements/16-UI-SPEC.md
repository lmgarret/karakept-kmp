## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (2.dp) | Tag chip vertical padding, compact metadata top padding |
| sm | 8px (8.dp) | Section title bottom padding, radio option start padding, field gaps |
| md | 12px (12.dp) | Compact layout horizontal padding, radio option horizontal/vertical padding |
| lg | 16px (16.dp) | Card content padding, toggle row horizontal padding, section padding |
| xl | 24px (24.dp) | Section breaks between editor setting groups |
| 2xl | 48px (48.dp) | Not used in this phase |
| 3xl | 80px (80.dp) | Bottom spacer in scrollable editor content |

Exceptions: 10.dp used for compact list row spacing (`Arrangement.spacedBy(10.dp)`), 12.dp for list row spacing (`Arrangement.spacedBy(12.dp)`). These are established patterns -- do not change.

**Source:** Existing `LayoutEditorScreen.kt` and `BookmarkLayouts.kt` spacing values.

## Typography

All typography uses `MaterialTheme.typography.*` tokens. No hardcoded sizes.

| Role | Token | Usage in This Phase |
|------|-------|---------------------|
| Section heading | `titleLarge` | Editor section headers ("Show", "Layout", "URL Display", etc.) |
| Option title | `titleMedium` | Toggle row labels, slider labels |
| Option label | `bodyLarge` | Radio option primary text, dialog list item primary text |
| Option description | `bodySmall` | Radio option secondary text, URL display in bookmark cards/lists |
| Card title | `titleMedium` | Bookmark title in List/Card layouts |
| Compact title | `bodyMedium` | Bookmark title in compact-style List layouts |
| Metadata | `bodySmall` | Date, reading time, URL/domain text in bookmark items |

**Source:** Existing `LayoutEditorScreen.kt` and `BookmarkLayouts.kt` typography tokens.

## Color

All colors use `MaterialTheme.colorScheme.*` tokens. No hardcoded hex values.

| Role | Token | Usage |
|------|-------|-------|
| Dominant surface | `surface` / `background` | Scaffold background, card container default |
| Card container | `CardDefaults.cardColors()` | All bookmark layout cards (list, card) |
| Secondary surface | `surfaceVariant` | Thumbnail placeholder background, progress track |
| Accent | `primary` | Selected radio icon tint, selected option icons, selection border, progress indicator, "Create new layout" button icon |
| Text primary | `onSurface` (implicit) | Title text, option labels |
| Text secondary | `onSurfaceVariant` | Description text, date, URL/domain display, option descriptions |
| Selection highlight | `primaryContainer` at 0.3 alpha | Selected bookmark card background |
| Active highlight | `secondaryContainer` at 0.3 alpha | Active bookmark card background (desktop) |

Accent reserved for: selected radio button icons in editor, "Create new layout" button icon/text, selection borders on bookmark cards, linear progress indicator.

**Source:** Existing `BookmarkLayouts.kt` and `LayoutEditorScreen.kt` color usage.

## Interaction Contracts

### Live Preview Updates

All toggle and radio changes in the editor MUST update `PreviewBookmarkItem` immediately (same frame). The preview composable already receives the full `BookmarkLayout` state -- new fields (`showDescription`, `showUrl`, `urlDisplayMode`, `urlPosition`, `descriptionPosition`) must be wired through identically.

### Migration Behavior (COMPACT_LIST to LIST)

When loading existing layouts with `layoutType == "COMPACT_LIST"`:
- Auto-map to `LIST` type
- Set `showDescription = false`
- Set `showTags = false` (preserve existing value)
- Set `thumbnailSize = 48` (preserve existing value)
- Set `metadataPosition = "BESIDE"` (preserve existing value)

The `COMPACT_LIST` enum value remains in `LayoutType.fromString()` for deserialization but maps to `LIST`. Built-in Compact preset becomes a LIST variant with compact defaults.

### Per-List Picker Navigation Flow

1. User taps "Layout" in per-list settings
2. `AlertDialog` opens with layout options + "Create new layout" footer button
3. User taps "Create new layout"
4. Dialog dismisses
5. Navigator pushes `LayoutEditorScreen(layoutId = null)`
6. User configures and taps "Save"
7. Navigator pops back to per-list settings
8. If user opens the layout picker again, the new layout appears in the list (via `allLayouts` StateFlow refresh)
